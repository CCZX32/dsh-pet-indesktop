# v4.3.4 — 语音与多屏的成体系修复

> **已发布**：2026-10-18。
> 上一版 v4.3.3 只存活数小时：它把多屏改成了单合成窗，也补上了台词语音与待办播报，
> 但一批**同类缺陷**当时没被一次找全。本版是一次成体系的收口，不是单点补丁。

## 为什么有这个版本

用户原话：「我不想再一直这样出一点小问题修一点了。」v4.3.3 发布后有两位用户报告：

- **#307**（`Hankui3x`）：混合缩放双屏（主屏 1920×1080@100%，副屏 3200×2000@200%）
  下桌宠**完全不可见、不可交互**；「点击台词朗读」开了也不出声。
- 另一位用户：升级到 4.3.3 后**点击台词仍然没声音**，并给出了 `config-slot-0.json`
  里键值变化的证据。

于是做了一次从 4.3.0 到 4.3.3 的**全面盲审**（两个独立模型 + 代码取证），把缺陷按
"模式"而不是"现象"归纳出来。本版修的是这些模式在代码里的**全部实例**，不只是被
报告的那两个点。

## 一、语音：读错了配置层（#307 问题二）

「点击台词朗读」有三个独立断点，任一都足以让它静默失效：

1. **`OverlayShell.cfg` 回的是主配置**。旧架构「一窗一宠」，`win.cfg` 天然是那只宠
   的视图；单合成窗之后它变成单例，`cfg` 退回主配置——而点击朗读判据、台词池、
   角色都读 `host.cfg`。`self_talk_speak_enabled` / `click_show_self_talk` /
   `character` 都是**每宠键**（真值在 `config-slot-N.json`），主配置里根本没有，
   于是判据恒为 False：**气泡照出、就是不朗读、连一行日志都没有**。
2. **音频通道的生命周期判据同样读主配置**（`_self_talk_speak_wanted`），通道可能
   根本没被建起来，或在下一次设置保存时被释放。
3. **`_self_talk_voice_configs` 读了不存在的底层表名**（`_instances`），legacy 拓扑
   下每次取每宠视图都抛 `AttributeError`，被上层 except 吞掉——所以 v4.3.3 的
   legacy 台词语音预缓存其实一直是坏的。

三处都改成读**每只宠此刻真正在用的那份视图**。设置页写进哪个档案，运行期就从哪个
档案读。

## 二、语音：缓存键不是「实际合成输入」的指纹

v4.3.3 的台词缓存以 `md5(文本)` 命名。后果：

- **换音色 / 改语速 / 换后端后，旧句子永远不会重合成**——试听已经是新声音，
  点击台词还是旧声音，重启也没用；edge 与豆包同句甚至落到同一个 mp3 路径。
- 报时缓存的键取"配置里写的音色"，而音色被 preflight 自动回退时实际合成音色
  已经变了——音频与文件身份不符。

现在缓存键由 `provider.flavor(values)`（实际合成输入）参与，即时合成 / 预合成 /
查找三处共用同一份 resolved attempt。外部脚本产出的经典文本 wav 仍作为**独立兼容
来源**保留，但不再凌驾于当前配置的产物之上。

顺带修掉预缓存的单飞语义：合成期间再次保存台词**不再被丢弃**（当前批结束后按最新
名单补跑），合成期间关掉开关**句间即停**（不再整批跑完）。

## 三、多屏：混合缩放会画到屏幕外（#307 问题一）

一张合成窗只能有一个 `devicePixelRatio`。窗口铺满整个虚拟桌面时，Windows 按「窗口
大部分落在哪块屏」给它定一个 DPR，于是必有一侧按错的倍率渲染——报告者主屏
1920×1080@100% + 副屏 3200×2000@200%（副屏物理面积更大）时窗口 DPR 取到 **2.0**，
主屏的桌宠整只被画到可见区之外：**气泡看得见、身体点不到**（他把副屏调成 100% 就
正常，正好证明是这个原因）。

**现在**：检测到各屏 DPR 不一致、且开了「允许桌宠跨屏」时，改成**每块屏一张合成窗**
——每张窗的 DPR 天然正确，不存在"按错倍率画"这回事。跨屏仍然是「拖过去」：
拖拽过程中光标进入另一块屏，就把这只连同位置交给那块屏的窗（局部坐标经全局中转），
鼠标仍被源窗捕获、事件坐标换算到它新的宿主窗，所以**是连续穿过去**，不是松手才跳。

关闭「允许桌宠跨屏」时不需要多开窗，仍只开一张、退化为启动那块屏的可用区。

> 上一版（v4.3.3）在这里做的是「窗口退化为启动屏」，能看见但不能跨屏；本版是正解。
> 日志不再打「跨屏本次不可用」。

## 四、多屏：拖过去的位置没存下来（v4.3.3 回归）

真实鼠标拖到副屏松手后，位置**不落盘**，重启回到旧屏。

根因是两套身份不同步：每 tick 只更新运行期的 `home_screen`，而持久化比较的是
`screen_name`／待写归属；**真实鼠标拖拽路径从来没有调过 `_remember_sprite_screen`**
（只有首撮落种与 `move_sprite_to_screen` 调它，而后者产品里没有调用点）。于是几何
自存看到"盘上屏名 ≠ 实际所在屏"，按「临时承载」整段跳过——一个几何键都不写。

现在拖拽收尾（钳制之后）按最终实际屏补记归属。拔屏的机械迁移仍走「临时承载」，
不会被误记成用户意图。

## 五、提醒：「命令发了」不等于「东西送到了」

`show_bubble()` 在「有审批提醒占着气泡」时**返回 False**，但待办提醒忽略了返回值
——而它**已经盖了 fired 戳**。结果：到点没气泡、没系统通知、之后也不再补。报时与
节日提醒的气泡是同一种写法。

现在「是否真的展示」成为一条明确契约（overlay 与 legacy 的 `show_bubble` 都返回
布尔），气泡没送出时改道系统通知；两条路都不通时留一条 warning，不静默。**不抢占
审批气泡**。

## 六、其他收口

| 修的东西 | 现象 |
|---|---|
| 每日待办跨午夜 | 23:59 的每日待办，电脑 00:00 恢复、只晚一分钟也不提醒（occurrence 只构造今天/明天，漏了"昨天那次仍在宽限窗内"） |
| 进程级服务的角色身份 | 换角色后灵动岛名称、主动识屏发给模型的宠物名、legacy 托盘勾选仍停在默认角色（都读全局 `character`，而它是每宠键） |
| 点击内容设置的显隐 | 只开「点击自言自语」时，候选台词 / 配图目录 / 配图概率 / 显示时长被隐藏（显隐依赖周期开关，而点击链路早就独立了） |
| 刷新率变更的通知范围 | 副屏从 60Hz 改成 180Hz，tick 仍按旧频率（取数枚举全部屏，但只订阅了窗口自己那块屏） |

## 六点五、交付前双模型审查修掉的（v4.3.4 收尾）

发布前用两个模型各做了一轮只读审查，交叉验证出同一批"按宿主分片"的缺口，本版修掉：

| 问题 | 现象 | 修法 |
|---|---|---|
| 屏拓扑不跟 `_hosts` 同步 | 拔掉副屏后宠留在失效宿主；插屏不建窗，拖不过去 | 新增拆窗流程（成员按比例并回存活宿主 + 关窗 + 断信号 + driver detach），插屏建宿主 |
| 窗口自己监听屏信号并重算整张桌面 | 改分辨率/任务栏/刷新率后副屏窗扩成全桌面，**#307 的显示错误原样复活**（探针 `1536×816 → 4480×1392`） | 窗口几何来源改成"它自己那块屏" |
| 跨窗移交删光位置监听、跟随器缓存旧原点 | 气泡停在旧位置、之后不再跟宠走 | 移交后重绑监听 + `set_origin` |
| 投影用当前位置反算"旧位置" | 旧像素擦不掉（残影） | 保存上次真正绘制的矩形 |
| 副屏右键菜单写主窗控制器 | 副屏选动画/移动没反应 | 按宿主取控制器，`no_move` 对所有宿主同步 |
| 快速聊天锚点用主窗原点 | **启动就在副屏的宠**一开聊天偏一整块屏 | 用 `_sprite_origin(sprite)` |
| 整窗显隐的 clip 恢复只走主窗 | 副屏宠完全静止、连帧都不换 | 取每张窗的成员表 |

## 七、没有修的（如实）

**issue #286**（Windows 11 + 150% DPI 下桌宠不可见、鼠标整屏失效）**仍未解决**，
本版不含它。报告者在 v4.3.1 上补了三条很有价值的观察：

- overlay 拓扑下 `WS_EX_TRANSPARENT` 常驻，`SetCursorPos` 移到身体中心也不取消 →
  看得见点不到；
- legacy 拓扑下拖不动、右键需「先左键激活」；
- `overlay-active-pets.json` 退出时被写成空、启动时不注册自己（代码注释写明这是
  「启动期不替用户改盘」的有意设计，所以这一条属产品语义争议，不是明确缺陷）。

前两条**需要 150% 缩放的真机环境加现场探针**才能定位，本机是 100% 双屏，无法复现。
不做「猜一个改法」的修复。

## 八、升级说明

- 无配置格式变更、无键改名、无迁移。
- 多屏缩放一致的用户行为不变；**混合缩放**用户每块屏各有一张窗，跨屏照常拖（v4.3.3 里「跨屏本次不可用」的说法作废）。
- **换音色后第一次点击/预缓存会重新合成**（缓存键变了），属预期。
